# Repository Guidelines

Plinth is a Vue 3 + TypeScript component library monorepo (pnpm + Turborepo). The published package is `@plinth/ui` (`packages/core/`). Component sources live in `packages/components/<seg>/`. Internal packages (`@internal/*`) are private.

## Commands

Use Node.js `>=20.19` with pnpm `>=10`. Install with `pnpm install`. Run `pnpm dev` for the playground and `pnpm dev:docs` for VitePress. `pnpm build` compiles `@plinth/ui`. `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `pnpm verify` cover the usual gates.

Add a component with `pnpm gen component`. Do not hand-edit generated files (`// generated by contract:sync`).

## Coding style

TypeScript and Vue 3 SFCs. Component directories use kebab-case. First-party UI components are prefixed like `PlButton`. Prefer `unknown` over casual `any`. Do not hand-edit `dist/` or `es/`.

Library SFCs use plain `<style>`, never `scoped` — including wrappers around third-party components. Isolation comes from the `pl-` class prefix, enforced by `vue/enforce-style-attribute` on `packages/**/*.vue`. Docs demos and playground code may still use `scoped`. The foundation does not ship Less or SCSS. The library author picks `none` | `scss` | `less` at `pnpm bootstrap`; `pnpm gen component` reads `preprocessor` from `lib.config.ts`. Published CSS stays CSS.

Class names come from `createNamespace` in `@internal/utils` (BEM: `pl-button`, `pl-button__content`, `pl-button--primary`, `is-disabled`); never hand-write the prefix in templates or TS. The prefix lives only in `lib.config.ts` and is generated into `packages/utils/src/css-prefix.ts` by `pnpm gen sync`. See `docs/guide/styling.md`.
